# yaranimka

Чат-бот сообщества ВКонтакте: раз в сутки присылает в беседу расписание серий,
которые выходят сегодня у текущих онгоингов, и отвечает на команды участников.
Говорит от лица сообщества — токен сообщества другого режима и не знает.

---

## Что делает

**Раз в сутки** в 10:00 по местному времени (настраивается) отправляет в беседу
дайджест: какие серии каких онгоингов выходят сегодня, номер серии и время.

```
🌸 Сегодня, 19 августа — 12 серий

• Клеватесс 2 — 7 серия, 16:00
  https://shikimori.one/animes/62513-clevatess-ii
• Гачиакута — 20 серия, 18:30
  https://shikimori.one/animes/58567-gachiakuta
```

**В любой момент** отвечает на команды в беседе:

| Команда | Что делает |
|---|---|
| `сегодня` | расписание на сегодня |
| `завтра` | расписание на завтра |
| `неделя` | ближайшие серии на семь дней, по дням |
| `аниме <название>` | поиск тайтла на Shikimori |
| `помощь` | список команд |

Команду понимает в любом виде: `сегодня`, `!сегодня`, `/сегодня`
и `@яранимка, сегодня`. Пока бот не администратор беседы, ВКонтакте вообще
не показывает ему сообщения без упоминания — поэтому упоминание снимается
перед разбором, а не мешает ему.

---

## Откуда данные

Расписание берётся из [календаря Shikimori](https://shikimori.one/api/doc)
(`/api/calendar`) — там русские названия, точные даты и время выхода серий.

Календарь отдаёт **по одной ближайшей серии на каждый онгоинг**, дальше в
будущее он не смотрит. Поэтому дневной дайджест точен, а недельная сводка
показывает по одному эпизоду на тайтл, а не все его выходы за неделю.
Это ограничение источника, а не бота.

Взрослое сортируется на стороне Shikimori (`censored=true`). Дополнительно
можно отсечь проходные тайтлы порогом оценки — `YARANIMKA_MIN_SCORE`.

## Настройка ВКонтакте

1. **Ключ доступа.** Сообщество → «Управление» → «Работа с API» →
   «Ключи доступа» → создать ключ с правом **«Сообщения сообщества»**.
   Это и есть `VK_GROUP_TOKEN`; там же под заголовком виден числовой
   id сообщества — `VK_GROUP_ID`.
2. **Long Poll API.** «Работа с API» → «Long Poll API» → включить,
   версия **5.199**. На вкладке «Типы событий» отметить
   **«Входящее сообщение»** (`message_new`).
3. **Сообщения сообщества.** «Управление» → «Сообщения» → включить.
   Без этого бот не сможет ни писать, ни читать.
4. **Возможности ботов.** «Управление» → «Сообщения» → «Настройки для бота» →
   включить. Кнопку «Начать» можно оставить — команда `начать` уже понимается.
5. **Беседа.** Добавить сообщество в беседу и **выдать ему права
   администратора беседы**. Без прав ВКонтакте показывает боту только
   сообщения с упоминанием — команды без `@` работать не будут.
6. **Номер беседы.** Открыть беседу в веб-версии: в адресе будет `?sel=c5`,
   где `5` — номер беседы. Это `VK_CHAT_ID`; готовый `peer_id` вида
   `2000000005` тоже принимается.

## Установка и запуск

```
git clone <репозиторий> yaranimka
cd yaranimka
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Заполнить `.env` и запустить:

```
python -m yaranimka
```

Бот встаёт на Long Poll, отвечает на команды и сам отправляет дайджест,
когда наступит назначенное время.

Другие режимы:

| Команда | Что делает |
|---|---|
| `python -m yaranimka` | обычная работа: беседа + дайджест по расписанию |
| `python -m yaranimka digest` | отправить дайджест за сегодня и выйти — для планировщика |
| `python -m yaranimka today` | напечатать сегодняшний дайджест в консоль, ничего не отправляя |
| `python -m yaranimka tomorrow` | то же на завтра |
| `python -m yaranimka week` | то же на неделю |
| `python -m yaranimka digest --dry-run` | проверить связку целиком, но без отправки |

Режимы `today`, `tomorrow` и `week` токен не требуют — на них удобно
проверять, что расписание тянется, ещё до настройки сообщества.

## Переменные окружения

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `VK_GROUP_TOKEN` | — | ключ доступа сообщества, обязателен |
| `VK_GROUP_ID` | — | числовой id сообщества без минуса, обязателен |
| `VK_CHAT_ID` | — | номер беседы или `peer_id`, обязателен |
| `YARANIMKA_DAILY_AT` | `10:00` | время ежедневной рассылки |
| `YARANIMKA_TZ_OFFSET` | `4` | часовой пояс в часах от UTC |
| `YARANIMKA_MIN_SCORE` | `0` | минимальная оценка тайтла для дайджеста |
| `YARANIMKA_MAX_ITEMS` | `20` | сколько строк максимум в одном дне |
| `YARANIMKA_LINKS` | `1` | ссылки на Shikimori в дневном дайджесте |
| `YARANIMKA_STATE_PATH` | `state.json` | файл памяти о последнем дайджесте |
| `YARANIMKA_DRY_RUN` | `0` | ничего не отправлять, только логи |

## Как бот не шлёт дайджест дважды

Отправленный день записывается в `state.json`. Перезапуск процесса в 10:05
не приводит к повтору: бот видит, что за сегодня уже отправлял.

Обратная сторона: если бот впервые запустился в 23:00, дайджест за этот день
уйдёт сразу — пусть и с прошедшими сериями. Молчать сутки хуже, чем прислать
расписание задним числом.

---

## Чтобы бот работал постоянно

Процесс должен быть запущен всё время — Long Poll живёт только пока бот висит
на запросе. Варианты:

- **Windows.** «Планировщик заданий» → задача при входе в систему,
  действие `python -m yaranimka`, рабочая папка — папка проекта.
  Для запуска как службы — [NSSM](https://nssm.cc/).
- **Linux.** Юнит systemd с `Restart=always`.
- **Только рассылка, без команд.** Если ответы на команды не нужны, можно
  обойтись без постоянного процесса: `python -m yaranimka digest` по крону
  раз в сутки.

Аварии бот переживает сам: обрыв Long Poll переподключается, ошибка Shikimori
или VK записывается в лог, и цикл продолжается через минуту. Падение процесса
целиком — это молчание в беседе, поэтому единичное исключение его не роняет.

## Тесты

```
pip install pytest
python -m pytest tests -q
```

Тесты сетью не пользуются: разбор команд, фильтры расписания, тексты сообщений
и нарезка длинных сообщений проверяются на фикстурах.

---

## Что бот не делает

- Не постит на стену сообщества — только сообщения в беседу.
- Не знает, где смотреть серию: Shikimori даёт факт выхода, а не ссылки на
  площадки.
- Не отслеживает конкретные тайтлы по подписке: дайджест общий по всем
  онгоингам, сузить его можно только порогом оценки.
